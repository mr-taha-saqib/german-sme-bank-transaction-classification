# v1.1.0-mlops: MLOps layer for the German SME transaction classifier

Branch `mlops-production-delivery` (PR #1). Acceptance evidence: `FINAL_E2E_ACCEPTANCE.md`.
The research pipeline, data, frozen split, augmentation corpus v2, seeds, 0.80 threshold and
all published results are **unchanged** (verified: split and corpus regenerate bit-identically;
19 + 11 + 66 checks, 12/12 integrity, 120/120 recomputations pass).

## Added
FastAPI inference (single + batch with per-item errors, 0.80 automatic/manual-review routing,
delayed-label feedback, Prometheus metrics, monitoring summary), versioned model registry with
checksums, explicit approval and rollback, MLflow tracking (10 published research runs imported
read-only), privacy-preserving monitoring (descriptions are never logged or stored) with PSI
drift checks, leakage-gated retraining with a validation-only promotion gate, Docker images +
compose, GitHub Actions CI, full documentation.

## Fixed
- Research `test_*` functions could never fail under pytest (checks were only recorded).
- README stated Python 3.10+, but the pinned numpy requires Python 3.12+.

## Model
GermanFinBERT seed 42, research configuration, trained on **CPU** (fp32): validation metrics
identical to the published GPU run; test group accuracy 0.697 (published GPU seed 42: 0.667;
authoritative five-seed mean 0.6485 ± 0.0271). Weights (≈ 420 MB) are not in the repository;
reproduce with `train_model.py` + `python -m src.model_artifact` (see DEPLOYMENT.md).
GPU re-verification was not possible in the delivery environment (no NVIDIA GPU available).

## Known limitations (read before use)
- **Trained and evaluated only on synthetic German transactions** (template-generated + LLM
  augmentation). No real banking data was used. **Authorised, labelled real transaction data
  from the client is required to validate (and likely retrain) the model before any business
  deployment.**
- 33 independent test groups (one group = 3 accuracy points); about one in five automatic
  decisions was wrong on the test set; confidences are uncalibrated and not a guarantee.
- CPU training ≈ 2 h per run (GPU recommended). No API authentication, TLS, rate limiting or
  cloud deployment. Not a production banking system.
